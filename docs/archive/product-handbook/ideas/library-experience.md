# Library Experience — Exploration

**Status:** Exploring
**Owner approval:** Exploratory preferences captured; not an approved feature specification.
**Origin:** Product brainstorming, October 2026.

## Owner's priority order

When using the library after accumulating a substantial collection, the owner ranked these outcomes from most to least important:

1. **Visual browsing and rediscovery** — Enjoy browsing the collection visually and stumbling across previously collected content.
2. **Fast retrieval** — Find a specific piece of content quickly when looking for something known.
3. **Meticulous organization** — Maintain carefully organized collections, but this is less important than browsing and retrieval.

## Browsing experience direction

The owner prefers a combination of:
- **Curated discovery entry point:** A visually rich starting view that can surface collections, favorites, recently added content, forgotten gems, or other useful groupings.
- **Expansive visual grid:** A direct path from that starting view into a broad, scrollable visual collection.

This is a preference about the overall experience, not a finalized layout or specific set of sections. The curated view should complement—not obstruct—the ability to browse the collection directly.

## Active rediscovery and personal curation direction

The owner wants Ayamai to participate proactively in rediscovery rather than relying only on manual browsing. The desired capabilities to explore include:

- **Content resurfacing:** Occasionally surface older content that the owner has not viewed in a while.
- **Automatic groupings:** Identify interesting relationships within the collection and create useful groupings without requiring manual organization.
- **Taste learning:** Learn from what the owner views, revisits, saves, favorites, and otherwise engages with, then use those signals to make curation and resurfacing more relevant.

The intended role is a personal curator for the owner's own collection, not an engagement-maximizing social feed. The collection remains the owner's; Ayamai helps them appreciate and rediscover it.

### How Ayamai should learn preferences

The owner prefers **both implicit learning and explicit feedback**:
- Learn naturally from behavior such as viewing, revisiting, saving, favoriting, and other engagement, minimizing required effort.
- Also provide deliberate ways to rate, like/dislike, or otherwise guide what Ayamai should show more or less of.

The exploratory preference is for implicit learning to do much of the work, with explicit controls available to correct and steer it. This is not approval of any particular tracking scope, signal set, labeling workflow, or data-retention policy.

These are exploratory capabilities, not approved algorithms, tracking policies, data models, or implementation requirements. The meaning of "viewed," the signals used, frequency and controls for resurfacing, transparency, and user control remain to be explored.

## Product implication to explore

The library should feel primarily like an enjoyable visual place to explore and rediscover a personal collection, not merely a database or file-management interface.

Search and filtering should support quick retrieval without displacing the visual browsing experience. Organization should be useful without making extensive manual categorization a prerequisite for enjoying the library.

These are exploratory implications, not implementation requirements. Do not infer specific layouts, algorithms, metadata models, or automation behavior from this preference alone.

## Open questions

- What makes visual browsing enjoyable for this collection?
- Which curated sections would genuinely be useful, and which would become clutter?
- How should rediscovery work: chronological browsing, random resurfacing, smart groupings, recommendation-like surfaces, or a combination?
- How often should older content be resurfaced, and how should the owner control or dismiss it?
- What signals should Ayamai learn from, and how should it explain or let the owner adjust that learning?
- What visual information should appear on each item before opening it?
- How should search and filters coexist with visual exploration?
- Which organizational tools are genuinely useful, and which would create unnecessary maintenance?
- Should the library offer different browsing modes for images, GIFs, and videos?

## Process note

Keep exploring concrete usage scenarios and preferences. Do not create Linear work or treat this document as an implementation brief until the owner explicitly commits to a direction.
